# Finance workspace lifecycle boundary

Workspace initialization, sharing edits and connected-evidence transfers now take the company boundary before user/space/domain locks and reread current account state after any wait. This matches account disable/purge ordering. Sharing retains its exclusive company lock for company-activity uniqueness; initialization/transfers use a compatible shared company lock. Ordinary Finance calculations, values, space policies and transfer-bundle rules remain unchanged.

The prior sharing route acquired the employee row before the company row, opposite account lifecycle, creating a possible deadlock. The prior transfer path could complete from stale authentication after disable. A delayed initializer could recreate default private spaces. These concrete paths are now serialized and reject locked/disabled actors using the canonical messages.

New helper `finance-space-access.js`; narrow hooks in `finance-spaces.js` and `finance-space-transfers.js`. The subsequent scoped-pool change below covers ordinary Finance transactions; unscoped provider/background writers remain part of the mixed-private-space purge audit. ## Scoped Finance transactions

The Finance pool now acquires the company lifecycle boundary and rereads the current actor before domain SQL. Explicit transactions hold it until completion. Single statements retain autocommit behavior, with the access check and statement inside one transaction. A fixed-scope, volatile SECURITY DEFINER function uses only the request's actor/company GUCs, takes company/user locks in canonical order and returns only lifecycle flags. Execute permission is revoked from PUBLIC and granted to the existing restricted Finance role. No arbitrary SQL or table write privileges cross that bridge.

Read-only report transactions recheck actor membership/status without row locks; PostgreSQL enforces their read-only state. Their existing snapshot semantics remain. MCP continues using its existing outer transaction. A context-local queue keeps each Finance scope setup/query/cleanup block together, and ordinary borrowed MCP queries join the same queue. Scope is reapplied for every borrowed Finance block and its restricted role is reset afterward. Closed contexts reject access; nested use is reentrant; errors release the queue. Existing request cleanup still completes before a durable MCP operation receipt can commit. No MCP tool schema/discovery changes or client refresh is needed.

Integration: additive/idempotent function installation runs from the existing `installFinanceSpacesSchema`; no table/data migration. Install schema with the updated source before serving the updated pool. `mcp/context.js` changes were explicitly coordinated with the integration owner. No production migration has been run.

## Plaid background lifecycle boundary

Plaid webhook sync uses the service pool rather than the scoped request pool. A provider response can therefore arrive after disable and write into a retained private space. The follow-up re-reads the current item/space and private owner under the company lifecycle boundary, before provider requests and again before database writes. Shared/selected/company spaces retain normal provider syncing even when the original uploader is disabled. Disconnected, missing or unassigned items fail closed. Provider calls remain outside database locks; receipt matching must use the same space and protected transaction. Tests use disposable PostgreSQL and a fake provider, including delayed responses and both lifecycle/write ordering cases. No production credentials or provider requests are needed.

## Selective private Finance purge

The deletion planner now removes independent personal bundles from legacy private spaces that also hold retained company history. It does not grant an administrator access to their contents. Explicit company-activity spaces remain intact. A reviewed table allowlist makes new/unknown Finance tables retained by default. Payroll, commission, mileage, time allocation, operational and Stripe history remain seeds; explicitly company-scoped AI memories and mismatched/unknown AI owners also remain. All actual FK constraints are inspected, including composite keys, external tables and CASCADE/SET NULL actions. UUID references in Finance snapshots, journals, AI actions and text are followed both inward and outward, preserving connected evidence. Unknown external references to a space retain its whole content. Known non-FK company sources from Worker 2 (jobs, quotes, payments, time/pay snapshots and material IDs) remain outside the deletion set.

Closed statement fingerprints summarize whole ledgers. If a closed private ledger contains any retained financial evidence, its accounting records stay intact even when the snapshot omits individual UUIDs. Independent personal tools still qualify unless linked to retained evidence. A wholly personal closed ledger remains deletable. No financial calculation, source value, historical identity or retained record is changed.

The graph is evaluated only during authorized preview/execute under the existing company lifecycle lock. It holds at most50,000 candidate rows/250,000 UUID references and retrieves identities rather than private text payloads; exceeding those limits returns `finance_retention_review_required` with no deletion. The exact selected row hashes, account revision and counts bind the confirmation token. This remains conservative: a text UUID mention can retain a connected bundle, and a future domain using non-FK, non-UUID associations requires a reviewed contract before its records can be considered private.

Receipt originals/thumbnails are queued only if no receipt outside the exact deletion set references either key. Shared/duplicate objects survive. Provider failures retain bytes in the existing retry queue. Reviewed retained receipt IDs are saved inside the existing durable purge summary so later storage totals continue to classify them as retained, including external-only references. Storage screen loads continue using metadata aggregates, not this graph or a bucket scan; the measurement text discloses conservative mixed-space categorization before deletion review is applied.

API: optional additive `private_finance_records_in_retained_spaces` count in deletion preview. New clients decode it optionally; old clients ignore it. `private_finance_spaces` counts fully removed spaces, and retained spaces may now have eligible independent records removed. Retention explanation is server supplied. No new MCP tool or private metadata exposure. No schema/data migration; apply after the existing lifecycle/Finance transaction/Plaid guards and prior purge adapters.
