# AI tasks in Automations

Search automation_catalog_page by section/query and read automation_node_schema for the exact reviewed trigger/action fields. Use automation_folders if the owner requested a specific existing workspace. Create a named draft, read its graph hash, save connected typed nodes through canonical graph validation, inspect the result, and publish only with the new exact graph hash and authorized policy. The legacy automation_catalog tool returns a compact overview; page reviewed entries with automation_catalog_page. The full native REST catalog remains available to human editors. Publishing a draft preserves Off or a timed pause; use automation_activation_schedule_set with the current automation_get record_hash to set or clear optional company/IANA once or weekly windows at second precision without starting a run, use automation_off for indefinite Off, automation_pause with a future pause_until for a timed pause, and automation_resume to turn an eligible published graph On. AI task config includes publishing execution_user_id, instructions, allowed_tools, verified model/reasoning, max_steps, estimated max_cost_micros, output_destination, output_title and failure_behavior. AI tasks cannot invoke automation control tools or native navigation. Existing scheduler/event deduplication and timezone/DST behavior apply. The action waits durably without advancing through approval. Each result is in its own conversation; private_note/company_note delivery uses note_create and its configured approval. Cancellation of the parent stops subsequent assistant work. Failure appears in the existing automation run/issues; error_path supports a separately authorized notification branch.
