# Notes, databases and access

Use notes_create_page for pages, folders, spaces and databases. notes_edit_blocks supports canonical typed blocks and exact block revisions. notes_share replaces the explicit member list and roles at the current page revision; it does not override conversation membership. notes_restore_version restores content while preserving current access and live children. Database definitions have a schema revision distinct from row revisions; read notes_database_schema, then supply both revisions when editing a row. Property IDs are stable schema keys, not display names. Values are validated by the current canonical property type, and links to people, files or Notes require current access. Unknown property IDs fail. A checklist can become a normal linked To-Do only for assignees who may read its source. notes_purge is permanent and only accepts a trashed Note owned by the actor at its current revision; it keeps a tombstone and does not delete original Media files or linked tasks. Prefer trash/archive when permanent removal was not requested. Native Notes navigation requires the newer Notes client integration described in the handoff.
