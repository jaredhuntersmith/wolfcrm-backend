# Editing existing automations and recurring AI work

Read automation_get/draft and automation_catalog, load automation_node_schema for each action/trigger you plan to edit, and use automation_graph_save with exact current graph_hash. It supports the existing engine’s triggers/actions, conditions, branches, waits, loops, parallel paths, ports, notes and safety settings. Draft save does not publish. Existing protected credentials remain redacted and unchanged; AI/role permission controls remain human-only. Publishing/resuming/executing recursively checks actual referenced published workflows. Dynamic child IDs require the normal human workflow. New catalog items default unavailable until explicitly reviewed.

Use automation_metadata_save for name/folder/concurrency/reentry/failure settings with record_hash. Existing draft cloning, duplicate/archive, run histories, draft dry tests, explicit published manual runs, cancel and recovery all use canonical services. Starting/retrying can execute external effects; exact approval and actual automations.run permission apply. Never claim cancellation undoes a completed effect. Dry tests cannot prove live provider delivery.

For a daily/weekly/monthly AI report, use time.schedule with schedule frequency, time HH:MM, timezone company or IANA; weekdays Monday1–Sunday7 for weekly, month_day for monthly. Default catch-up window15 minutes, configurable1–120. Only published enabled rules run; no backfill before publication. Missing DST wall times or calendar dates skip, repeated wall time fires once. The existing durable scheduler deduplicates automation/node/local date, rechecks pause/version and supports restart recovery. assistant.task binds the published author/current grants, chosen funding/model, bounded steps/cost and explicit allowed tools. It waits durably, saves a configured Note once, or follows the existing error path. Scheduled reports retrieve fresh authorized data, not old chat prose.
