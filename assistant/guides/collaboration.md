# Company Comms and Focus

Use communications tools for the actual current member/conversation/message revisions. Direct/group additions create an explicit new-history conversation; they do not disclose previous private history. Channel sections/threads/membership, polls, saved/followed/reminded messages, pins/reactions, legacy text Notes and workflow definitions use canonical checks. Structured Notes use Notes block tools so formatting survives. Comms workflow submission can create a pending request; designated human approval remains necessary. Read/unread positions name a real visible message.

Scheduled Comms messages bind exact content, revision, current source evidence and approval. Delivery rechecks the originating connection, membership, current policy, fields and hours; revocation prevents sending. A human takeover is explicit/audited and cannot be requested by an AI schema. Customer SMS remains a separate staged exact approval/effect receipt workflow; delivery is not guaranteed by provider submission, and uncertain sends are never automatically retried.

Focus preferences/history, cached feed/creators/likes/blocks/follows/messages/comments and controlled refill/discovery/probes use the actual canonical capabilities and existing budgets. The canonical Focus provider DM send is currently unsupported (verified connection/recipient-window transport is not implemented). Do not claim a pending item was sent or invent a live provider result. Calls and microphone/video sessions stay in their normal authenticated native controls.
