# Finance workspaces and authoritative accounting

Every financial operation requires an explicit permitted finance_space_id. Discover current typed finance capabilities and read canonical source hashes/versions before edits. Personal spaces stay private; Business operational sources require deliberate company-activity activation. Finance mutations use the explicit finance:write scope, current capabilities, owner/private-space authority, field policy, exact approval and durable request receipts. Historical OAuth scopes are unchanged; a denied scope requires normal owner reauthorization, not a workaround.

Use canonical services for accounts/balances, planned items/recurrence, debt/payoff/payment history, budgets/goals, transaction splits/reconciliation, balanced journals/reversal, receipt details/matching/lifecycle, recurring analysis/evidence, bank source/transfer accounting, time/mileage cost allocations, payroll policies/evaluation/journals, receivables, payment applications/credits and settlement evidence. Do not derive profit from sales or fill missing coverage with zero. Amounts are integer cents; supplied source versions and exact source hashes are required. Recording an already-made payment, contribution or accounting journal never initiates a bank transfer, customer charge, refund, payout or wage disbursement.

Bank login, consent/token exchange, reauthentication and credential administration remain the existing authenticated human controls. A configured consented bank refresh uses the real backend provider and can incur provider costs. New receipt photo/file acquisition uses the real native capture/upload path; never fabricate image bytes, storage object keys or OCR confidence. Private files require their own current storage authorization. Provider configuration is separate from internal implementation; ordinary accounting does not require a live provider.
